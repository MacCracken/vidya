## Version

- **Vidya**: 2.9.0 (canonical source: [`../../VERSION`](../../VERSION); `cyrius.cyml` reads it via `${file:VERSION}`)
- **Cyrius pin**: 6.7.15 (in [`../../cyrius.cyml`](../../cyrius.cyml)). The installed wrapper is newer (6.7.18), and it **dispatches on the manifest pin**: inside this repo `cyrius version` reports `cyrius 6.7.15 / manifest-pin: 6.7.15`, and `cyrius which` resolves `~/.cyrius/versions/6.7.15/bin/cycc`. A plain `cyrius build` therefore compiles with the pinned toolchain, and no override is needed. ⚠ `CYRIUS_HOME` takes the **install root** (`~/.cyrius`), not the versioned dir. Pointing it at `~/.cyrius/versions/<pin>` makes the resolver look for `<pin>/versions/<pin>/lib` and fail. ⚠ **Never run two cyrius commands in this tree at once.** Every `cyrius run` / `build` re-resolves `[deps.vyakarana]` and briefly moves `lib/vyakarana.cyr` aside, so a build alongside the content gate fails with "cannot hash lib/vyakarana.cyr".
- **Binary size**: **~2.76 MB static ELF** (`build/vidya`, 2,762,208 B), up 79,176 B (**+3.0 %**) from 2.8.7's 2,683,032 B. The dependency bump alone took it to 2,820,176 B (+137,144). Right-sizing two top-level arrays then gave back 57,968 B of static data, because a bare top-level `var x[N]` is N i64 *slots*, not bytes (see CHANGELOG 2.9.0 Fixed). Split with two scratch builds: the 6.7.15 compiler over the *6.6.20* lib is 2,674,840 B (**compiler −8,192**); the 6.7.15 snapshot with vyakarana 2.4.3 is 2,897,752 B (**stdlib +222,912**, mostly `bayan` 1.9.0 at +180,407 B of source, plus the `math` and `unicode/` modules it now pulls in); and vyakarana 2.9.1's compacted grammars take **77,576** back. Static data *fell* 515,728 → 193,664 B with the bump (sigil's 256 KiB bank buffer left `.bss`), then → 135,696 B with the array fix. **cyrius does not run DCE by default**, so unreachable code ships: 3,232 → 3,502 fns, 1,075,594 → 1,270,715 B. A `CYRIUS_DCE=1` build is 1,550,416 B. Still far below 2.8.0's 14.66 MB (**−81.2 %**). `serve` remains plaintext localhost and never executes the crypto or PDF code at runtime.
- **Corpus**: 77 topics × 11 languages = 847 examples; coverage gaps = 0 (P4 complete: build_systems + package_resolution + reproducible_builds, shipped 2.7.3)
- **Source layout**: `src/main.cyr` (598 lines — CLI plumbing, route table, `main()`) + `src/vidya_core.cyr` (1,573 lines — types, registry, TOML loader, hot-reload, search, compare, code, validate, and the `json_*` builders). Split at 2.8.2 so `tests/vidya.tcyr` and `tests/vidya.bcyr` can `include` the domain layer: a `.tcyr` cannot bind a port and could not reach into a file whose only entry point is `main()`. Tests and benchmarks now run the same code the binary serves.
- **Gates**: `cyrius test` **140 assertions** (+1 at 2.9.0: `missing_id`), `cyrius bench tests/vidya.bcyr` **12 benchmarks**, content gate **847/847** under `VIDYA_STRICT=1` on the CI toolchain set. Zig is pinned at **0.17.0** as of 2.8.7, matching the dev host. CI checks the tarball's sha256. 2.8.6 recorded the gap that forced the move: 810/37 on the host, all `zig.zig`.
- **Benchmark baseline reset at 2.8.6**: `lib/bench.cyr` was rewritten between 6.6.2 and 6.6.20 (windowed per-op means instead of a floor-subtracted per-sample minimum), so `target/bench-history` snapshots from before 2.8.6 are **not comparable** with later ones. It is byte-identical 6.6.20 → 6.7.15, so 2.8.6 onward compare directly. **`reg_get_hit` and `reg_get_miss` are not stable rows at any pin**: hashmap seeds from `getrandom` per process (since cyrius 6.5.39), so collisions on the probe path change per run. Misses ranged 49–726 ns and hits 87–394 ns over the 2.8.6 and 2.9.0 harness-free runs. Confirm a move in either with several processes, never one bench run.
- **Gate depth (new at 2.8.3)**: the content gate no longer just compiles-and-runs. Rust gets an additive `--test` pass, Go gets `gofmt -l` + `go vet`, TypeScript is `tsc --noEmit --strict` type-checked before running, Python runs with `EncodingWarning` as an error, and any Cyrius `duplicate fn` fails the build. ⚠ Every one of these is mirrored in `validate_command` in `src/vidya_core.cyr` — the two validators drifted twice in the 2.8.x series and each time the shipped CLI silently skipped work the shell gate ran. **Still invisible to the gate**: comment-level falsehoods, semantics it never executes (no OpenQASM circuit is simulated), and anything a language's own tooling does not flag.

### ⚠ sakshi: why it is NOT a git dep

cyrius folded sakshi into its stdlib snapshot at **6.5.24**. Through 2.8.0 vidya still declared `[deps.sakshi]` at tag 2.4.4, and `cyrius deps` overlays a git dep's resolution **on top of** the folded snapshot on every build — so the 2.4.4 file was *replacing* the toolchain's 2.4.10. It was a silent downgrade with three tells, all now gone: `duplicate fn 'sakshi_span_enter' / 'sakshi_span_exit' (last definition wins)` on every compile; `cyrius deps --verify` reporting clean because the lock is written **from disk** and recorded the hash of the downgraded file; and the stale copy being pushed at anything reaching vidya transitively. sit hit the identical trap and dropped its pin for the same reason — see the `[deps]` comment in `~/Repos/sit/cyrius.cyml`. **Do not re-add the git block.** Pinning sakshi means pinning the toolchain, and the `cyrius` pin in `[package]` is that lever.

### Stdlib modules

From `cyrius.cyml` `[deps] stdlib` (**25 modules**): `syscalls, string, alloc, str, fmt, vec, hashmap, io, fs, process, chrono, tagged, bayan, ct, keccak, sigil, fnptr, args, regex, net, dynlib, tls, fdlopen, sandhi, sakshi`. (`process` was added post-2.8.1 for `exec_cmd` in `vidya validate`; it was already on disk as a transitive, so the vendored file count is unchanged — declaring it is what keeps it from being someone else's transitive, the class of dep that fails at **runtime**.) A clean `rm -rf lib cyrius.lock && cyrius lib sync && cyrius deps` vendors **75 entries** into `lib/` (declared set plus transitives, plus `vyakarana.cyr`). The count was 62 through 2.8.3, 63 at 2.8.4 (6.5.35), 65 at 2.8.5 (6.6.2), 73 at 2.8.6 (6.6.20), and 75 at 2.9.0 (6.7.15). At 6.7.15 the two new entries are `math.cyr` and a `unicode/` directory (casefold / categories / normalize tables), both pulled in by bayan 1.9.0. The 6.6.20 additions are all transitive, and nothing new was declared to cause them: `async` plus `async_agnos` / `async_macos` / `async_win` (via `sandhi`), `random` and `sys` (via `sigil`), `tls_hostid` (via `tls`), and `alloc_cx` and `poison` (via `alloc`). **`assert.cyr` left again.** It is the test-assertion library that 2.8.4 recorded entering the shipped binary through `sakshi`'s `panic()` and `alloc`'s `fail_after_n_allocs()`. Overwriting a stale *declared* module still works as it has since 6.5.29: re-verified at 6.6.20 by staging the 6.6.2 `fmt.cyr` and watching `cyrius lib sync` restore it. ⚠ **A pin bump is no longer safe in place, though.** `lib sync` refreshes only the declared subset and re-locks at the new pin. `cyrius deps` then refuses every transitive leaf still holding old-pin content: 15 at 6.6.2 → 6.6.20 (`atomic`, `hashseed`, `result`, `boxed`, `slice`, `freelist`, `mmap`, and the `thread*` / `sync*` families). `deps --relock` gets past the refusal but keeps the orphaned old-pin `assert.cyr` vendored and locked. So the clean rehydrate above, which CLAUDE.md called belt-and-braces from 2.8.1, is **required** from 6.6.20. Note this is what makes a **git-dep overlay** the dangerous case: the overlay is reapplied on every build *by design*, so it is not staleness the sync can heal — see the sakshi note above.

**6.1.x consolidated the former standalone `json` / `toml` / `base64` modules into the bundled `bayan` distlib** — those `lib/{json,toml,base64}.cyr` no longer ship, so `src/main.cyr`, `tests/vidya.tcyr`, and `tests/vidya.bcyr` `include "lib/bayan.cyr"`. **The 6.2.x→6.4.x sandhi/TLS refolds grew the transitive surface**, adding five modules that had to be listed explicitly (the cyrius transitive resolver doesn't chase refold-added enum/const/call-site refs): `chrono` (`clock_now_ns`/`clock_now_ms`, sandhi keep-alive), `dynlib` (`dynlib_auxv_get`/`dynlib_read_auxv`, `fdlopen`), and `sigil` + `ct` + `keccak` (`sha384_init_into`, `tls_native`). Re-measured at 6.5.29 during the 2.8.1 bump: the arc has caught up for three of the five — dropping `ct`, `keccak`, `sigil` still vendors the same 62 modules and builds clean (binary 4,080 B smaller), so those three are now redundant rather than load-bearing. `chrono` and `dynlib` remain hard requirements (removing either is a build error). All five are kept regardless, because an undeclared module of this class fails at **runtime**, not at build time — see roadmap "2.7.x dep-track follow-ups".

**The five `undefined function` warnings are gone as of 6.6.20.** Through 2.8.5 every build warned on `random_bytes`, `async_new_in`, `async_spawn`, `async_run`, and `async_await_readable`. At 6.6.20 their definers (`lib/random.cyr`, `lib/async.cyr`) are vendored as transitives, so the names resolve. Nothing in vidya calls them: `serve` is synchronous and plaintext. So they are DCE-dead code in the binary rather than undefined references. At 6.6.20 a build still warned about `lib/sigil.cyr`'s 256 KiB crypto-bank array local. **At 6.7.15 that is gone too**: a build prints only the unreachable-fns note, the large-static-data note (193,664 B), and the `hashmap_fast.cyr` "outside the declared footprint" note, which is harmless (`lib sync` copies it as a declared-subset sibling, and `deps` no longer resolves it).
