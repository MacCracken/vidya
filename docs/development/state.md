### ⚠ sakshi: why it is NOT a git dep

cyrius folded sakshi into its stdlib snapshot at **6.5.24**. Through 2.8.0 vidya still declared `[deps.sakshi]` at tag 2.4.4, and `cyrius deps` overlays a git dep's resolution **on top of** the folded snapshot on every build — so the 2.4.4 file was *replacing* the toolchain's 2.4.10. It was a silent downgrade with three tells, all now gone: `duplicate fn 'sakshi_span_enter' / 'sakshi_span_exit' (last definition wins)` on every compile; `cyrius deps --verify` reporting clean because the lock is written **from disk** and recorded the hash of the downgraded file; and the stale copy being pushed at anything reaching vidya transitively. sit hit the identical trap and dropped its pin for the same reason — see the `[deps]` comment in `~/Repos/sit/cyrius.cyml`. **Do not re-add the git block.** Pinning sakshi means pinning the toolchain, and the `cyrius` pin in `[package]` is that lever.

### Stdlib modules

From `cyrius.cyml` `[deps] stdlib` (**25 modules**): `syscalls, string, alloc, str, fmt, vec, hashmap, io, fs, process, chrono, tagged, bayan, ct, keccak, sigil, fnptr, args, regex, net, dynlib, tls, fdlopen, sandhi, sakshi`. (`process` was added post-2.8.1 for `exec_cmd` in `vidya validate`; it was already on disk as a transitive, so the vendored file count is unchanged — declaring it is what keeps it from being someone else's transitive, the class of dep that fails at **runtime**.) A clean `rm -rf lib cyrius.lock && cyrius lib sync && cyrius deps` vendors **75 entries** into `lib/` (declared set plus transitives, plus `vyakarana.cyr`). The count was 62 through 2.8.3, 63 at 2.8.4 (6.5.35), 65 at 2.8.5 (6.6.2), 73 at 2.8.6 (6.6.20), and 75 at 2.9.0 (6.7.15), still 75 at 2.9.1 (6.7.18): the same file set, 39 changed and 42 byte-identical. At 6.7.15 the two new entries are `math.cyr` and a `unicode/` directory (casefold / categories / normalize tables), both pulled in by bayan 1.9.0. The 6.6.20 additions are all transitive, and nothing new was declared to cause them: `async` plus `async_agnos` / `async_macos` / `async_win` (via `sandhi`), `random` and `sys` (via `sigil`), `tls_hostid` (via `tls`), and `alloc_cx` and `poison` (via `alloc`). **`assert.cyr` left again.** It is the test-assertion library that 2.8.4 recorded entering the shipped binary through `sakshi`'s `panic()` and `alloc`'s `fail_after_n_allocs()`. Overwriting a stale *declared* module still works as it has since 6.5.29: re-verified at 6.6.20 by staging the 6.6.2 `fmt.cyr` and watching `cyrius lib sync` restore it. ⚠ **A pin bump is no longer safe in place, though.** `lib sync` refreshes only the declared subset and re-locks at the new pin. `cyrius deps` then refuses every transitive leaf still holding old-pin content: 15 at 6.6.2 → 6.6.20 (`atomic`, `hashseed`, `result`, `boxed`, `slice`, `freelist`, `mmap`, and the `thread*` / `sync*` families). `deps --relock` gets past the refusal but keeps the orphaned old-pin `assert.cyr` vendored and locked. So the clean rehydrate above, which CLAUDE.md called belt-and-braces from 2.8.1, is **required** from 6.6.20. Note this is what makes a **git-dep overlay** the dangerous case: the overlay is reapplied on every build *by design*, so it is not staleness the sync can heal — see the sakshi note above.

**6.1.x consolidated the former standalone `json` / `toml` / `base64` modules into the bundled `bayan` distlib** — those `lib/{json,toml,base64}.cyr` no longer ship, so `src/main.cyr`, `tests/vidya.tcyr`, and `tests/vidya.bcyr` `include "lib/bayan.cyr"`. **The 6.2.x→6.4.x sandhi/TLS refolds grew the transitive surface**, adding five modules that had to be listed explicitly (the cyrius transitive resolver doesn't chase refold-added enum/const/call-site refs): `chrono` (`clock_now_ns`/`clock_now_ms`, sandhi keep-alive), `dynlib` (`dynlib_auxv_get`/`dynlib_read_auxv`, `fdlopen`), and `sigil` + `ct` + `keccak` (`sha384_init_into`, `tls_native`). Re-measured at 6.5.29 during the 2.8.1 bump: the arc has caught up for three of the five — dropping `ct`, `keccak`, `sigil` still vendors the same 62 modules and builds clean (binary 4,080 B smaller), so those three are now redundant rather than load-bearing. `chrono` and `dynlib` remain hard requirements (removing either is a build error). All five are kept regardless, because an undeclared module of this class fails at **runtime**, not at build time — see roadmap "Waiting on a trigger".

**The five `undefined function` warnings are gone as of 6.6.20.** Through 2.8.5 every build warned on `random_bytes`, `async_new_in`, `async_spawn`, `async_run`, and `async_await_readable`. At 6.6.20 their definers (`lib/random.cyr`, `lib/async.cyr`) are vendored as transitives, so the names resolve. Nothing in vidya calls them: `serve` is synchronous and plaintext. So they are DCE-dead code in the binary rather than undefined references. At 6.6.20 a build still warned about `lib/sigil.cyr`'s 256 KiB crypto-bank array local. **At 6.7.15 that is gone too**: a build prints only the unreachable-fns note, the large-static-data note (136,336 B at 2.9.1), and the `hashmap_fast.cyr` "outside the declared footprint" note, which is harmless (`lib sync` copies it as a declared-subset sibling, and `deps` no longer resolves it). At 6.7.18 the bump first added 21 `'toml_get' is deprecated` warnings (bayan 1.11.0), and 2.9.1's rename removed them, so the build is back to those three notes.
